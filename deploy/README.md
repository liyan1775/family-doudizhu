# 临时公网与后续长期部署

0.4.0中，双击根目录 `启动游戏.cmd` 自动建立临时公网入口并生成二维码，家人可用手机流量或其他Wi-Fi加入。首次自动准备Cloudflared，日常无需账户、域名或路由器设置。来源、网络边界和实现见 [临时公网方案](../docs/public-room.md)。

临时入口需要电脑保持开机联网，关闭或重启清空房间，旧二维码失效。没有长期固定地址或可用性保证。`启动局域网游戏.cmd`保留同一Wi-Fi备用方式；旧局域网服务可与新公网服务分别运行。

以下是后续长期部署的预留要求，尚未作为本轮升级的已完成项。

部署对象是带实时房间服务的 Node.js 应用，不能只上传网页静态文件。

## 预留要求

1. 单实例运行 `npm ci`、`npm run build` 和 `npm start`。
2. 域名使用 HTTPS，反向代理保留 `/socket.io/` 的 WebSocket Upgrade 和长轮询能力。
3. 用 `.env` 的 `PUBLIC_BASE_URL` 设置正式二维码根地址；密钥不进入 Git。
4. 当前房间保存在内存，重启会丢失。正式上线前完成持久化、房间恢复、备份和运行监控。
5. 微信 Android/iOS 真机验证扫码入口和音频播放。只通过桌面浏览器检查不算微信验证。
6. 公网开放前收紧访客频率限制和网络信息接口，确定隐私与访问策略。
