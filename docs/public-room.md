# 一键临时公网房间

更新日期：2026-10-04。版本：0.4.0。

## 已确认的产品流程

用户要求一键启动临时公网入口、自动生成二维码，家人在同一局域网或其他网络都能扫码加入，无需安装手机软件、配置网络或手动输入地址。用户本轮明确选择继续手机开桌：第一位家人扫码后选人数并创建房间，后来的人扫主页码点桌或扫房间码加入。电脑不占玩家座位。

## 本次实施方案

采用 Cloudflare Quick Tunnel。它提供随机的临时 HTTPS 地址，无需主机注册账户、购买域名或在路由器上开放端口；停止联网进程后地址失效，每次新建地址会变化。这些能力和临时服务边界见 [Cloudflare 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)。服务商选择是实施方案，并非用户指定供应商。

`启动游戏.cmd` 调用现有准备流程的公网模式：

1. 沿用已有的本项目公网进程；连续双击通过系统持有的本机启动锁协调。临时运行记录不能授权终止任何残留PID。
2. 在独立的 `dist/public/client` 和 `dist/public/server` 构建。旧局域网服务及其 `dist/client` 文件继续保留；两个入口分别管理自己的房间。
3. 跳过已有服务的端口，游戏只监听 `127.0.0.1`。Windows可能允许回环地址与通配地址共用端口，因此选择端口时还检查已有HTTP服务并试占完整IPv4端口，避免遮蔽旧主机。
4. 自动下载固定版本 `cloudflared`，按官方SHA-256校验完整文件后才使用。组件保存在Git忽略的 `data/tools/cloudflared/`，不安装系统服务；以后校验并复用缓存。首次慢网允许最多15分钟下载，每15秒显示收到的大小；这是可调的实施参数。
5. 用明确的空配置和独立子进程连接本机服务，避免继承个人隧道配置或环境中的 `TUNNEL_*` 参数。默认使用HTTP/2和IPv4建立出站连接；无需手机或路由器设置。
6. 拿到地址后，核对公网健康接口的项目与本次实例标识，先检查Socket.IO WebSocket请求及回执，失败再检查HTTP长轮询；至少一种可用才上线，检查不会创建玩家座位。检查通过后，以进程IPC同步地址，才打开电脑二维码页。网页优先使用WebSocket；连接失败或8秒超时后，下一次自动重连先使用HTTP长轮询，避免一直困在握手无响应的连接中。参数依据 [Socket.IO官方说明](https://socket.io/docs/v4/client-options/)。Cloudflare支持WebSocket，见 [官方FAQ](https://developers.cloudflare.com/cloudflare-one/faq/cloudflare-tunnels-faq/#does-cloudflare-tunnel-support-websockets)。
7. 定期检查公网入口，连续失败时收起二维码；同一联网进程恢复后重新显示相同地址。联网组件退出时提示结束本次启动后重新开桌，不自动切换地址导致手机身份存储丢失。
8. 关闭启动器后，游戏服务和联网管理子进程通过IPC断开自行退出；联网管理进程只结束自己启动的组件。保留原局域网游戏和其他应用。

电脑页可保存二维码或复制邀请链接。手机房间邀请也使用本次公网地址并提供保存二维码；同源PNG接口只生成本次已就绪入口与存在的房间，不接受任意目标地址。公网接口不列电脑内网IP；动态入口更新没有对外HTTP管理接口。原座位令牌、动作版本检查和仅发本人手牌的协议继续使用。临时主机只对来自回环隧道的、格式合法的 `CF-Connecting-IP` 进行访问者限额统计，防止所有家人的动作被错误合并。

## 组件来源

- Cloudflared `2026.9.3`，[官方发布与校验值](https://github.com/cloudflare/cloudflared/releases/tag/2026.9.3)，[官方源码及Apache-2.0许可证](https://github.com/cloudflare/cloudflared)。2026-10-04读取官方发布接口核对Windows x64资产为55,366,080字节，SHA-256为 `f096265ec2fcbe9bb6e2d64268db167ced3fcbb83d894bdb9e2fcdb26f2ea7e2`。
- 下载地址与不同架构的固定校验值保存在 `scripts/temporary-tunnel.mjs`；升级时必须重新核对官方资产并更新记录，不自动运行未经核对的最新版。
- Windows x64为本轮运行目标。Windows ARM使用官方x64组件的兼容路径，Windows 32位和Linux资产也有固定映射，这些平台未作为本轮实机验收结果。

## 当前边界

- 主机电脑需安装Node.js 22.12或以上；已有项目运行环境无需新增手动配置。手机无需安装软件。
- 临时公网服务无可用性保证，网络或微信对临时域名的访问限制仍可能影响扫码。启动器会检测这台主机到公网入口的连通性，不能替代家人的流量网络、Android微信与iPhone微信真机测试。
- 使用期间电脑须开机联网，不能休眠。关闭或重启清空内存中的房间和积分，旧二维码失效。没有跨域名迁移手机身份或重启恢复牌局。
- 拿到本次二维码／链接的人能看到可加入的桌并入座；本轮沿用无需账号、填称呼的已确认流程。
- 若公网无法建立，可明确选择 `启动局域网游戏.cmd`，这个备用入口要求同一Wi-Fi。不会把局域网二维码当成成功的公网结果。
- 稳定域名、长期在线服务、持久化和正式运营部署仍是后续工作。

## 真机验收

1. 电脑双击启动，第一部手机用微信扫码开二／三／四人桌。
2. 第二部手机关闭Wi-Fi，用移动流量扫电脑主页码点桌加入；另一位家人从其他Wi-Fi扫房间码加入。
3. 每人只见自己的手牌，准备后完成叫分、出牌、声音提醒、结算与下一局。
4. 同一手机刷新和短时切网恢复原座位；主机短时断网后恢复同一入口。
5. 重复双击保留同一房间；结束后关闭启动窗口，旧码不能使用，重开提供新码。
6. Android微信与iPhone微信各记录扫码、音频、后台返回和完整牌局结果，桌面检查不替代真机结论。
