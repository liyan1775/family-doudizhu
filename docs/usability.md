# 牌局可用性检查与改进方案

检查日期：2026-10-03。核查基线为0.2.2源码；0.3.0已完成叫分／身份播报、回合提醒和牌桌布局，0.3.1继续修正手牌比例。下文保留修复前证据与已审阅方案，实施结果见本页末尾和testing.md。

## 用户已确认的选择

- 报牌参考流行的经典斗地主游戏，强调自然、短促、有重音和力度。女声小样已认可；男声的声调和力度未通过，用户明确要求后续再调，先交付其他功能。
- J叫“勾”，Q叫“皮蛋”，K叫“凯”，A叫“ace”；Q的单张、对子、三张分别为“皮蛋／对皮蛋／三个皮蛋”。牌面继续显示J、Q、K、A。
- 轮到本人时采用明显的视觉变化和一声短提示音，替换反复播放的“轮到您了”。
- 用户补充：普通报牌有声音，主要是叫三分或最后一次叫分没有声音。
- 地主确定时，各自手机播报“您是地主／您是农民”即可；不要求语音读出任意玩家称呼。画面仍明确显示地主名字。

## 核查结果（0.2.2修复前）

| 问题                                       | 结论与证据                                                                                                                                                                                                                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 报牌语气不足、Q叫法不符合家庭习惯          | Q在`scripts/voice-lines.json`中为“圈／对圈／三个圈”，A为“尖”，J为“钩”。当前四套素材由通用神经音色合成，仅设置语速、音高及句末感叹号，并进行静音裁剪和响度处理。用户听感反馈成立；是否达到新的自然度和力度需用新样本听审，代码和桌面检查不能量化证明其优于或等于商业游戏。            |
| “轮到您了”冗长且不及时                     | `App.tsx`收到新事件后先`playEvent`，再将`your-turn`追加到同一个播放队列；会等前面的报牌完成，没有针对回合提示的过期检查。视觉变化是上方座位框高亮和牌桌文字变化，手牌区域及操作栏没有对应的明显回合样式。                                                                            |
| 看他人余牌数需要来回滚动                   | 手机样式把四个完整座位卡分成两行，包含头像、姓名、身份、张数、积分。它们使用普通文档布局。四人地主33张手牌复现中，375×667和390×844窗口的页面均约1643px高；滑到手牌下部时，余牌和回合文字都已离开屏幕。只有操作栏是底部sticky。                                                       |
| 三分或最后一次叫分没有播报、地主身份易错过 | `game.ts`的`bid()`在三分或最后一人叫分分支直接`chooseLandlord()`，未生成该次`bid-*`或`no-bid`播报。实际复现`[3]`、`[1,0,2]`、`[1,2,0]`均只留下`audio: ['landlord']`作为最后事件。素材“地主确定，开始出牌”没有指出谁是地主；服务端随即进入playing，普通事件文字很容易被首手出牌替换。 |

补充：普通中间叫分已有正确音频键；在隔离源码预览中，一分、两分、三分及地主MP3均返回200和`audio/mpeg`。本次漏播是事件路径缺失，不能以“文件存在”认定播放完整，也没有证据表明全部叫分都缺声音。

证据截图：[375px牌桌上部](screenshots/ux-review-375-table.png)、[375px手牌下部](screenshots/ux-review-375-hand.png)。截图仅包含测试玩家，属于桌面浏览器模拟手机尺寸。

## 已审阅的实施方案

### 1. 完整叫分和明确宣布身份

- 保留每次叫分／不叫／叫地主／抢地主的播报，包括结束叫分的最后一个动作；之后再宣布地主身份。
- 同一次服务端动作可能产生“叫分”和“地主确定”两条播报。将它们表示为有序的语义片段，并分别保留操作者，避免末位不叫的人与最终地主不是同一个人时用错音色。继续使用原事件编号作为操作版本，不因增加音频片段破坏重复动作校验。
- 地主确定后，每部手机播放自己的身份：“您是地主”或“您是农民”。所有手机以大字显示“某某当地主”，自己的手牌区和常驻余牌栏持续显示地主／农民标识。
- 建议提供约1至1.5秒的身份宣布展示，结束后显露正常出牌操作；不增加每人点击确认的流程。最终展示时长是实施参数，结合手机试玩调整。
- 宣布身份属于重要播报，不能被普通出牌音频队列裁剪丢失。无需新增联网称呼合成；继续随网页提供静态素材。

### 2. 本人回合立即可见

- 根据服务端`turnId`立即更新自己的手机：持续高亮手牌区域／底部操作区域，显示大字“请出牌”或“请叫分”。别人回合显示“等某某出牌／叫分”。
- 回合到达时用一次短暂边框亮起增强注意，之后保留稳定高亮；遵守减少动态效果的系统偏好，不持续闪烁。
- 仅轮到本人的手机播放一次约0.2秒的短提示音。提示音不等待整个报牌队列，可短暂压低报牌／配乐，避免打断牌型或把多人手机同时变成提醒声。
- 在离线暂停、座位被替换、返回后台、回合已改变时撤销旧提示；重复状态不得重复响。恢复页面时立即显示当前轮次，避免补播积压的旧回合声音。
- 移除日常回合中的`your-turn`口播；保留出牌、叫分、身份和结算声音及明确文字。

### 3. 他人余牌常驻

- 牌局上方改为紧凑的常驻余牌栏，主要显示每位对手的姓名、剩余张数、地主／农民和当前行动标记；自己的张数放在手牌标题，积分、邀请等移到次级入口。
- 手牌较多时，让手牌区滚动，余牌、当前需要压过的牌和出牌操作仍可见。短屏无法全部容纳时，首先保证余牌栏与底部回合／操作区不离开视野，再压缩牌桌留白。
- 保持大字与至少48px主要操作按钮；不通过缩小所有文字解决高度问题。四人33张手牌、长称呼、系统放大字体都要检查。
- 仍只显示他人张数，不增加任何对手手牌数据。
- 对话中的可切换界面是方案示意：上／下半段按钮用于展示手牌位置变化后其他信息仍在同一位置，正式游戏沿用触摸滚动，不新增手牌翻页步骤。

### 4. 重新制作报牌小样

- 实施参考选择为腾讯[《欢乐斗地主》](https://hlddz.qq.com/)这类经典短句风格；用户没有指定该作品，也不据此宣称它的当前市场排名。参考的是节奏和力度，使用项目自己的素材。
- 先准备两种语气的小样：爽朗有力、明快自然。保留按座位区分音色的既有方向。
- 小样内容至少包括：勾、对皮蛋、三个皮蛋、凯、ace、对ace、一分、三分、不要、炸弹、您是地主、您是农民。
- 不把加速或提高音量当作自然度已改善的证据。先听清咬字、句尾收束、重音、不同音色一致性，再确定整套制作方式。若现有制作工具的表演控制不足，比较具备语气控制的合成方式或录音素材后再定。
- 参考技术：[微软SSML语气与语音控制](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-voice)。这些控制只适用于支持对应能力的服务与音色，当前Edge制作脚本不能直接视为支持全部SSML风格。
- 新文案和素材采用新资源版本路径，保留原件、来源与制作参数，并更新缓存路径，避免手机继续播放旧Q／A叫法。

## 实施顺序

1. 修复结束叫分的播报，补充本机身份音频和明显的地主展示。
2. 一并调整常驻余牌栏和本人回合视觉反馈、短提示音，避免只把上方提示换个颜色而仍滚出屏幕。
3. 新叫法和更有表现力的小样听审，通过后制作整套音频与新版缓存资源。
4. 完成规则事件／音频队列／回合去重等验证及手机尺寸检查，安排Android微信和iPhone微信完整试玩。

## 验收条件

- 第一位直接三分、末位叫更高分、末位不叫、全员不叫重新发牌、二人抢地主结束等情况都有对应动作播报和正确身份宣布。
- 末位行动者不同于最终地主时，叫分音色和身份消息仍正确。
- 同一动作重试不重复处理；刷新或重连不补播旧叫分、旧身份和旧回合。地主身份始终可查。
- 轮到本人收到新状态就显示明显变化，短提示音仅本机一次；回合改变后没有迟到的旧提示。
- 从手牌上端看到下端，始终能找到全部对手的余牌数和当前行动提示；17、20、25、33张和二／三／四人布局均检查。
- J/Q/K/A对应勾／皮蛋／凯／ace，四个座位的单张、对子、三张一致；原始牌面仍易认。
- Android微信和iPhone微信实测首次声音授权、叫分、身份、短提示音、关闭／恢复声音、切后台返回、断线和大字布局。桌面通过不能代替这些设备结果。

## 0.3.0实施结果

- 结束叫分事件包含末次动作与地主宣布的有序片段，分别保留操作者；每部手机据自己身份播放“您是地主／您是农民”。普通叫分、三分、最后不叫、重新发牌和二人拒抢／第四抢均有验证。
- 地主确定后大字显示称呼，1.4秒展示期间本机操作暂停；地主标记和本机身份持续可见。展示时长是实施参数。
- 本人行动时手牌和操作区持续金色高亮，边框两次短暂亮起；本机独立220毫秒短音不等待语音队列。首次／刷新／恢复状态作为基线，重复、过期或后台消息不补播旧提醒；离线、后台及换轮停止旧提示。
- 牌局使用屏幕高度布局，余牌与操作留在视野中，手牌内部滚动；“牌桌”可查积分、规则、邀请和服务端允许展示的底牌，继续只发送本人手牌。
- 声音路径升级classic-v2，文案覆盖勾／皮蛋／凯／ace及个人身份，四套各78句。采用已认可小晓女声方向；男声保留原参数，不采用未通过的小样和实验声调处理。
- 52项自动化验证、生产构建通过；四人33张牌在375×667屏幕内滚动时，余牌栏位置和底部操作保持固定；320×600检查无整页溢出。二人17／20张、三人末次叫分后20张、四人10字称呼的常驻余牌与完整详情检查通过；314个运行MP3均可解码。真实.cmd启动0.3.0与重复复用通过，测试服务已关闭，详见[验证记录](testing.md)。
- 男声gōu阴平与中气调试、系统／微信放大字体、Android及iPhone微信声音授权与后台返回仍待后续核对，不能把桌面结果当作真机通过。

## 0.3.1手牌比例修正

用户补充：部分手机手牌区不足两行，各区域应按比例占空间，尽量一眼看全。原版在320×600中手牌只有约106px，固定82px一行，确实不足两行；上轮检查只确认没有整页溢出和余牌固定，遗漏了手牌可见面积不足。

手牌改为按可用宽高分行错叠，扣除顶部和大按钮后优先获得空间。33张在320×568首屏分成三行，每张牌的点数、花色和独立点击范围仍可辨认；375×667及390×844同样全部可见。320×500完整显示两行22张，末行可以内部轻滑，其他区域保持固定。17／20张通常为两行。恢复声音移至顶部，避免刷新后额外占一行。最新截图与55项验证见[验证记录](testing.md)。

实施比例15／25／60、牌角最小23px及牌高最小50px是为可读性和触控采用的参数。密集牌角的实际手指选牌、具体手机型号和放大字体仍待微信真机反馈；不把桌面中心点点击检查写成真机触控已通过。
