# 技术与产品决策

## 2026-10-05：单一分享二维码评估

状态：用户确认玩家无需游戏以外的操作，分享码尽量统一，优先自动分流，除非实现明显复杂。尚未替换0.5.0双入口实现；用户未选择扫码后再手动选网络。

一个分享码可以进入同一个公网入口；全部实时消息走公网时，手机不需区分网络，但家中玩家也会绕行临时隧道，不能视为满足先前局域网直连体验的要求。另一个可实施方向是共用分享码先打开入桌页，首次点“在家／异地”，记住选择，再进入对应地址；这减少分享端的选码操作，保留局域网直连，但首次打开统一入口仍需要公网可达，页面之间的身份恢复需沿用各站点存储并单独验证。

全自动、公网优先打开后探测HTTP内网，受混合内容与本地网络权限限制。支持新权限的浏览器在授权后可放宽部分限制，但不能推定微信Android／iPhone均支持；来源：[MDN本地网络访问](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access)、[MDN混合内容](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)。固定域名、可信证书与家中DNS分流是另一条需要主机／路由配置的评估方向，当前无配置与真机结果。用户回复的“尽量自动，除非实现麻烦”已记录为产品原则；当前临时模式无法仅靠通用网页保证静默自动分流，未将不可靠探测或全部绕公网当作满足局域网体验的结果，也未修改路由器或购买域名。

## 2026-10-05：同桌双入口、横屏、换桌与30秒出牌（0.5.0）

状态：恢复局域网体验、参照三张用户参考图渲染横屏、扫码新桌优先、30秒出牌、旧桌本局取消不计分，均由用户明确确认。以下技术细节为实施方案，微信真机体验待验。

同一次启动监听 `0.0.0.0`，隧道仍连接回环地址；电脑默认展示“同一 Wi-Fi · 更快”，另可选“异地／流量”。两个入口共用房间、轮次、积分。手机邀请默认沿用本页入口，局域网页可切换公网分享，不自动改变正在游玩的域名；与旧版独立局域网启动器仍分端口、构建和内存，不迁移旧牌局。

采用两个明确入口以兼容微信内核：HTTPS页面中的HTTP私网请求可能受混合内容和本地网络权限限制，不能保证一个公网页面自动直连所有手机。依据：[MDN混合内容](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)、[本地网络访问](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Local_network_access)。内网IP只返回给无代理头的本机／私网请求，经隧道访问不列内网地址；PNG只接受本次已就绪公网入口或本机实际局域网地址。

牌局与结算页用横向布局，等待页便于填字。竖屏窗口旋转整张牌桌和弹窗，普通横屏直接显示；本人在底边，三人左右，四人加对家，二人对手在上方。手牌按可用宽高错叠，优先完整显示牌角。图片只参考布局，未复制商业游戏角色或素材。

新房间号优先于旧身份；已有称呼自动入座，首次无称呼先填写。服务端先校验目标房间、容量、阶段、称呼和旧令牌，再换座；失败保留旧局。换出正在进行的旧桌时清空本局、手牌，不结算，不改变累计积分；移交房主，其余家人重新准备。随机入座标识及短期回执用于回复丢失后的重试；同房间扫码或普通刷新仍恢复原座位。

倒计时只用于出牌阶段，由服务器持有期限：新回合30秒，普通消息／刷新不重置；有人掉线保存剩余时间，恢复后继续。超时跟牌调用“不出”，首出选最小点数单张；沿用规则、胜负和声音校验。叫分／叫抢继续手动，没有全局机器人托管。取消旧局、结算、退出、关闭服务时清理计时器，客户端只显示时间。

局域网和公网属于不同站点，浏览器不共享座位存储。切网后继续原入口恢复；扫码自动换桌在同一站点已有身份时验证，跨域名识别／迁移同一手机身份尚未实现。

## 2026-10-04：一键临时公网入口（0.4.0）

状态：跨网络扫码、无需手机安装／网络配置／输入地址，以及保留手机开桌流程，均由用户本轮明确确认；下面是已采用的实施方案。

双击 `启动游戏.cmd` 自动准备临时HTTPS入口，连通检查通过后展示电脑二维码。首位家人在手机上选人数开桌；后来的人扫主页码点桌或扫房间码加入。电脑可以保存邀请图片以便分享给远方家人。

采用Cloudflare Quick Tunnel，无需账户或自有域名。自动下载、固定版本校验和缓存由启动器处理；不要求家人安装软件或配置路由器。供应商、HTTP/2／IPv4、首次下载15分钟预算、入口检查频率与连失败次数属于实施参数，不是用户指定或保证的服务标准。来源与限制见 [临时公网方案](public-room.md)。

公网游戏监听回环地址，动态地址只通过IPC更新，公网配置不公开内网地址；验证HTTP、本次实例及至少一种实时连接的请求回执后才展示二维码，WebSocket受限时可使用HTTP长轮询。临时入口中断时收起二维码，同一进程恢复后继续原入口；进程退出后提示重新开桌，不跨新域名静默迁移身份。关闭主启动窗口结束游戏和自己创建的隧道进程，旧码失效。

网页采用WebSocket优先、8秒超时后重试先使用HTTP长轮询，保留原自动重连；同源PNG接口提供主页与房间二维码下载。连接顺序、预算和导出方式属于实施参数。桌面公网测试中存在间歇超时，经自动重试完成五种整局；用户移动流量初测主页可达但实时连接失败，修正后仍须复测。

公网和局域网分别使用构建、启动记录、端口和内存房间；旧局域网牌局保留，备用入口改为 `启动局域网游戏.cmd`。Windows选择公网端口时额外避免回环监听遮蔽已有通配监听。房间仍在内存，临时体验不以持久化完成为前提；长期部署与稳定域名另行处理。

微信Android／iPhone、真实移动流量及异地家庭网络的体验仍须真机验收，不能从桌面验证推定为已通过。

## 2026-10-03：稳定的双击启动（0.2.1）

状态：用户明确要求 `.cmd` 启动稳定、便于非程序员操作；以下为已采用的实施方案。

启动器先识别运行中的本项目游戏，重复打开沿用原服务，保留房间、手牌和积分；不在牌局运行时重新构建其静态文件。新健康接口包含服务标识、版本与项目路径的哈希，不公开实际文件路径或身份令牌。首版没有服务标识，兼容条件为请求端口上的健康接口、与本地完全一致的游戏首页、游戏配置结构同时匹配；该兼容路径只复用，不终止或接管旧进程。

用只监听回环地址的系统套接字协调同一项目的启动，避免连续双击并行安装、构建或创建两个房间服务。程序退出后系统自动释放启动锁，运行记录失效时重新检查，不根据残留PID结束其他程序。

首次使用准备锁定依赖，代码或输出变动时重新构建。构建记录包含源码、配置、正式资源和输出文件的内容校验；文件缺失或损坏不能视为可复用的构建。该记录与临时运行信息均在Git忽略目录内。

家庭试玩默认从3000开始尝试最多21个端口，被其他程序占用或无权绑定时使用下一个。监听成功并核对健康身份后才打开浏览器，二维码以服务实际端口为准。配置的本机HTTP网址可同步端口；固定外部网址或反向代理不能自动迁移端口，提供维护者可处理的中文提示。备用端口范围、构建缓存和自动打开是实现默认值。

启动器只管理自己创建的子进程；关闭、退出或IPC断开时结束该服务，已有的游戏和其他程序保持运行。中文提示、UTF-8编码、失败停留与浏览器打开失败时的手动网址，使日常操作仍是双击。旧服务复用时，更新要等本局结束并关闭原游戏窗口后再启动生效。

## 2026-10-03：电脑主机二维码与手机房间列表（0.2.2）

状态：入口流程用户已确认；以下为已采用的实施方案，微信扫码待真机验证。

用户明确电脑作为主机，运行 `.cmd` 就展示二维码。第一位家人扫码进入主页，在手机上创建房间；后续家人既可扫电脑的主页码，也可扫房主的房间码。用户选择主页直接展示可加入的房间，点一下加入。

启动器打开 `/?host=1`，主机页只读取连接配置和生成主页二维码，不建立玩家连接、不恢复座位或启动音频。手机二维码指向普通主页，不携带 `host`、`room` 或片段参数；排除回环地址，保留实际端口，并提供重查网络和多地址选择。默认优先配置的有效外部地址，再选择家庭局域网地址；这是实施默认值。

服务端提供 `/api/rooms`，只列等待入座、未满且至少一人在线的桌，按最近活动排序。摘要仅含房间号、房主称呼、人数和规则；不向目录发送身份、手牌或积分。手机首页约3秒更新，可手动刷新，点选直接使用该房间号提交原入座请求，最后一个座位仍由服务端校验。电脑主机页10秒检查连接、单次请求5秒超时是可调参数。

原3000端口的旧进程在本次功能验证中保留；新版在独立3100端口验证。房间列表需要运行新版服务，不能仅替换静态网页。重启会清空内存中的房间和积分，启用前需确认没有要保留的牌局。
