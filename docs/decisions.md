# 技术与产品决策

## 2026-10-03：扫码入口

状态：用户已确认。

使用微信内网页（H5）。房间二维码包含网页地址和房间号。

## 2026-10-03：长期文件管理

状态：已采用。

使用 Git 管理源码、文档和正式资源。按网页、服务端、规则、测试、脚本和部署配置分目录；文档用固定文件持续维护。

## 2026-10-03：牌局统一判断

状态：实施方案。

发牌、轮次、出牌合法性和结算在服务端执行。客户端负责显示和提交动作，规则模块不依赖浏览器。

## 2026-10-03：声音

状态：实施方案，微信真机效果待验证。

随网页提供普通话音频文件，避免将核心播报完全依赖于手机的语音合成接口。进入页面时提供声音试听，处理播放被浏览器阻止的情况，核心消息同时显示文字。

参考：[MDN 自动播放说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。微信特定行为必须以 Android/iOS 微信实际测试为准。

## 2026-10-03：设备、人数与网络

状态：用户已确认。每人一部手机，支持二人、三人、四人，同一 Wi-Fi 先试玩，后续上线。

## 2026-10-03：盐城亭湖规则

状态：已调研并提供可选配置，默认项需家庭试玩核对。

公开资料没有可靠的区域覆盖率统计，不能宣称任一玩法是“亭湖最广泛”。四人按多家产品共同基础默认江浙四人，另提供江苏废炸；二人默认46张抢地主，另提供54张简化版。来源、差异和程序约定记录在 `rules-research.md` 与 `rules.md`。

## 2026-10-03：技术与运行边界

状态：已实现。一个 npm 项目管理 React／TypeScript 网页、Node.js／Socket.IO 服务端与纯 TypeScript 规则模块，依赖由锁文件固定。单进程内存房间支持掉线恢复；服务器重启后不恢复房间。正式上线前另行实现持久化。
